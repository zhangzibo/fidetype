## Summary
One paragraph. What does this FEP change?

## Motivation
Which problem does it solve? Who needs it? Give a real use case (a device, a decoder, a dataset).

## Proposal
The exact change. Use MUST, SHOULD and MAY as in RFC 2119. Give the new field names, types, values and stability levels.

## Examples
Show a stream before and after the change, in at least one serialisation.

## Compatibility
- Is this a breaking change for producers? For consumers?
- How do old files and old readers behave?
- Which stability level does the new part start at? (Normally: Development.)

## Reference implementation
How does `fidetype.streams.spec` change? Which validator checks and conformance cases are new?

## Alternatives
Which other designs did you consider? Why did you reject them? Does another standard (LSL, BIDS, IEEE P2731, OpenTelemetry) already solve this?

## Privacy and leakage
Can the change carry personal data or ground-truth text? If yes, how do the rules prevent it?

## Open questions
Questions that the review must answer.
