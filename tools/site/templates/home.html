The problem

Fluent text is not always true text

A decoder and its language model can write fluent text that the person did not mean. On a flat, no-signal input, the language model still writes a sentence. An app that always types the top guess types that sentence.

The answer

Three answers for every sentence

Commit COMMIT

The guard is confident. It types the text.

Offer OFFER

The guard is not sure. It shows a short list. The user picks one.

Withhold WITHHOLD

The signal does not support any text. It shows nothing.

You choose alpha, the largest wrong-commit rate that you accept (default {{claim:alpha}}). The rate counts wrong commits out of all sentences, not out of the commits only. Fidetype sets the guard on your labelled data. It refuses a guard that commits on no-signal input. Read what the guarantee says.

    Get started

    Install in one line

    Three SDKs, one format. All three must give the same verdict on every conformance test.

    {{install_tabs}}

    Wrap your decoder (Python)

    import fidetype.trust as ft

# labelled outputs of your decoder + its outputs on no-signal input
guard = ft.calibrate(outputs, true_texts, alpha={{claim:alpha}},
                     null_inputs=no_signal_outputs)
r = guard(my_decoder(signal))
print(r.action, r.text)        # commit i need help

    Shortened. The full quick start runs with a fake decoder in a few seconds. No data needed.
