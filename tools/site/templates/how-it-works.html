2 / 6

One sentence, three answers

For each sentence, the guard asks two questions. Only a commit types text by itself.

Question 1. Is the top score at or above the commit threshold, and does the commit gate pass?

YES → COMMIT Type the text.

Question 2. If not: does the short list probably hold the right text?

YES → OFFER The user picks one or none.

NO → WITHHOLD Type nothing.

The commit gate is always on. It blocks an empty commit. In the NTS format, withhold is the action ABSTAIN or ASK (ask the user to try again). Apps act only on a final decision.

How the guard is set

You give labelled examples of your decoder's output: what it guessed, and what the person meant. Fidetype splits them at random into three parts.

Fit{{claim:split_fit}}
Policy{{claim:split_pol}}
Test (Learn then Test){{claim:split_ltt}}
Fit ({{claim:split_fit}})Makes the decoder's scores match its real accuracy. Sets the conformal threshold.
Policy ({{claim:split_pol}})Picks the guard limits and the offer size for typing speed.
Test ({{claim:split_ltt}})Sets the commit threshold with an exact statistical test. It is used for nothing else.
With probability at least 1 − δ over the draw of the calibration data, the wrong-commit rate of the guard on new sentences from the same distribution is at most α. Wrong-commit rate = wrong commits / all sentences. Defaults: α = {{claim:alpha}}, δ = {{claim:delta}}.

Last step: the no-signal test

In an early test, a re-tuned setup committed on {{claim:null_hit}} of {{claim:null_n}} no-signal streams. So now every calibration runs two no-signal controls, for example near-uniform input and time-shuffled input. If the guard commits on them more than alpha allows, Fidetype refuses the guard.

Not guaranteed

  • Any single sentence.
  • Each user, day or session alone.
  • Data that differ from the calibration data.
  • A typing speed. The guard can commit rarely.

The bound holds only if new data come from the same distribution: same user, device, sensor position, decoder and task. Re-calibrate when the use changes. The full guarantee sheet.

Inside an NTS stream

A stream is one header and a sequence of typed events. Select an event to see what it holds.

No raw signal. A stream carries decoder output only, never the raw recording. Decoded text is personal data. Files: JSON Lines or NPZ. Live: Lab Streaming Layer (LSL) or WebSocket.
