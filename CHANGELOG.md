## [Unreleased]

### Added
- `fidetype.trust.offer_gate`: time-direction frame features `time_asym`, `nb_time_asym`, `nb_decay_asym` (they change sign when the frame order is reversed; `DIRECTION_FEATURES`, `time_asymmetry`), and negated gate features (`OfferGate("-nb_time_asym", 0.0)`; `OfferGate.base`, `OfferGate.value`). No packaged gate changes (P14-57).
- `fidetype.trust.integrity` (P5-36): frame-order integrity check `check_frame_times` / `check_events` -> `IntegrityReport` (codes `frame_order_reversed`, `frame_order`, `frame_duplicate`, `frame_times_shape`, `frame_times_not_finite`, opt-in `frame_gap`; default tolerance = TIM-2 "strictly increasing"). `TrustGuard.decide(x, frame_times=...)` and `GuardSession.push(chunk, times=...)` run it on the producer's times: a stream that fails gets WITHHOLD (`ABSTAIN`) with a `stream integrity check failed` reason and an `integrity` audit record. Opt-in; a separate integrity layer, not part of the frozen configuration: no `config_id` changes, and no decision changes on a stream whose times increase strictly. It cannot see a fault that reverses the frame values while the times stay in order (the P14-57 `rev_out` input).
- `fidetype.trust.offer_gate`: offer-gate feature `lm_direction` (logits input, needs a character LM): forward minus backward LM log-probability per character of the greedy CTC text; it changes sign exactly when the frame order is reversed (`greedy_text`, `lm_direction`). No packaged gate changes (P5-36).
- `fidetype.trust.offer_gate`: offer-gate feature `lm_beam_direction` (logits input, needs an LM-beam readout: `OfferGate(..., readout=model.lm_readout())`): the frames are decoded forward and time-reversed with the LM beam, and the feature is the best-beam score difference per token, `(S(x) - S(rev x)) / ((n(x) + n(rev x)) / 2 + 1)`; it changes sign exactly when the frame order is reversed (`beam_score`, `lm_beam_direction`; `TrustGuard.offer_readout` for analysis). It costs two beam searches per scored offer. No packaged gate changes (P5-36b).
- `fidetype.pretrained.lmreadout`: `hd_quantile` (Harrell-Davis quantile), `quantile_lo` (a `ScoreGate` lower-bound rule that does not use the smallest real score) and `ScoreGate.with_lo`. No packaged gate changes (P14-58).

### Changed
- `willett-hw` LM readout (P14-59, gap 182; user decision 2026-11-22): the no-signal gate C5 threshold `lo` is now 0.566 (P14-58 rule; was -1.170). Time-shuffled test input emits text 0 / 80 (was 2 / 80); 3 / 80 real test inputs are gated (was 1 / 80); gated test CER 0.177 (was 0.175). The LM guard is calibrated again with this gate: new release file `willett-hw.lm3.guard.json`, `config_id` `tcfg-f498c0637536daec` (was `tcfg-26ae951a20a0cddd`); its `coherence` offer gate is refitted by the P14-54 rule (0.003486; was 0.002821); its offer null control passes (frame-shuffled 0 / 300). The default greedy readout and its guard do not change.
- Pretrained manifests: a trust block that ships an `offer_gate` must carry an `offer_control` block with verdict `"pass"`, or the parser raises `ManifestError` ("refuse" policy for gated guards). The default of `fidetype.trust.calibrate(offer_control=...)` stays `"warn"`. All packaged manifests pass (user decision 2026-11-22, gap 152).
- `TrustGuard` computes the features of a list of offer gates one gate at a time: a later gate's feature is computed only if the earlier gates pass. The decisions and reasons do not change (P5-36b).
- Device-support matrix: the `lsl` transport is now `replay-only` (was `synthetic-only`). The 816 real B2T '25 test trials of M4-06 went over a real pylsl loopback: decisions equal the in-process replay and the batch harness (816 / 816), 161,503 `double64` frames bit-equal (P4-21, [results](experiments/2026-11-22-p4-21-lsl-replay/results.md)).
- Device-support matrix: the `text-nbest` row cites real CSV and JSON Lines reads of B2T '25 decoder output (1,718 online 1-best texts, 816 10-best lists): exact round trip, 0 conformance failures. The files come from a converter, because no local tool writes these forms (P4-22, [results](experiments/2026-11-22-p4-22-nbest-readers/results.md)).

## [0.1.0] - 2026-11-21

First public release (PyPI). Version 0.0.1 was a development version and was never published.

Spec support (rule SDK-V1; matrix in spec section 11.7):
- NeuralTextStream v0.1 streams: read, write, check. The default written `spec_version` is `"0.1"`.
- NTS 1.0 RC4 (draft): decision `spec_version` and TD-9 (RC1); header `spec_version` (RC2; reads `"1.<minor>"`); RC3 rules (VER-8, GEN-10, TD-F2 `declaration`); RC4 rules (GEN-11 optional field types, MET-3 planned namespaces, TD-4 check `NTS-TD-INPUT`, MET-12 advisory check `NTS-LICENCE-MATCH`).
- Profiles: `v0.1`, `fep-0001` … `fep-0005`.

Install: `pip install fidetype`. Extras: `[hdf5]` (`pip install "fidetype[hdf5]"`: h5py for the HDF5 files of `fidetype.pretrained` and the emg2qwerty sessions; `[emg2qwerty]` stays as an alias of `[hdf5]`), `[lsl]`, `[brainflow]`, `[ws]`, `[data]`, `[llm]`, `[sign]`. Python 3.12 or later.

### Base (development version 0.0.1)
- NeuralTextStream v0.1 reader, writer and validator; NTS 1.0 RC2 header and decision `spec_version` support.
- Trust core and streaming trust layer (calibration, conformal sets, COMMIT / OFFER / ASK / ABSTAIN), intent (FEP-0003) and control (FEP-0005) trust layers.
- Conformance suite with the v0.1 and fep-0001 … fep-0005 profiles.
- Adapters: Lab Streaming Layer (`[lsl]`), BrainFlow bridge (`[brainflow]`), WebSocket (`[ws]`).
- Open benchmark v0.1 harness, provenance ledger, collector v0 (FEP-0006), offline demo.
- Console script `fidetype`.

- **OpenBCI GUI packet drops and two more real GUI v5+ files (P4-18, gap 157).** The `openbci-gui` reader now checks the Cyton `Sample Index` (0..255, wraps; step 1, or 2 on Cyton + Daisy; a wrap is not a drop). A jump is a packet drop. With `on_drop="gap"` (default) every row is kept, the rows after a drop get the correct later times, and the result lists `gaps` as `(row, missing_frames)`. `open_source` passes them to `ArraySource`: the first chunk after a drop carries `gap` (LSL-G3 fields, `cause` = `sample_index`), so `fidetype live` cuts the open segment and writes one `lsl_status` `gap_abort` record. `on_drop="error"` raises `ValueError`. A repeated index raises. Whole lost index cycles come from the time stamps. Other boards (Ganglion) are not checked (`openbci.sample_index_checked` false). New meta keys `openbci.packet_drops`, `openbci.samples_lost`. `ArraySource` takes `gaps=[(row, missing_frames)]`. Real files (outside the repository, never committed; `tests/test_adapter_openbci_gui_real.py`, env `FIDETYPE_P4_18_DATA`): a Cyton GUI v5.0 file with seconds stamps and 20 real drops (GPL-3.0) and a Cyton + Daisy GUI v5+ file with seconds stamps and an all-zero `Marker Channel` (CC BY 4.0). No openly licensed real file with non-zero markers was found.

- **Frozen external per-prefix scores in `calibrate` (P5-35, gap 165).** `fidetype.trust.calibrate(..., commit_unit="prefix", prefix_score=score)` certifies a prefix score fitted outside the library. `score` is a `fidetype.trust.FrozenPrefixScore(fn, name=, version=, spec=)` (module `fidetype.trust.external_score`): `fn(ctx)` gets a `PrefixContext` (top-1 words, calibrated n-best, frame log-probabilities for logits input, built-in prefix rows) and returns one score per word prefix or `None`. Calibrate fits nothing: the same LTT on the LTT items (loss "wrong prefix commit"), commit gate and null controls as the P5-24 prefix guard. The digest of `name`, `version` and the JSON `spec` is in the frozen configuration (schema `fidetype.external-prefix-score/0.1`), so it is part of `config_id`; the guard file keeps the digest and the spec, and `ft.load(path, prefix_score=score)` refuses a missing or different score. The sheet names the score and adds one assumption (the score did not see the LTT items). Other guard files and `config_id`s do not change. Check: the P11-16 LX-FL guard (EMG, research only) reproduced through the new path (`experiments/2026-11-21-p5-35-external-prefix-score/`). Tests: `tests/test_trust_external_prefix_score.py`. Text: docs/trust-guarantee.md section 10b.1.

- **Real-file check of the `edf` and `openbci-gui` readers (P4-16, gap 134).** Both readers now read real public files (outside the repository, never committed): PhysioNet EEGMMIDB `S001R01.edf` / `S001R04.edf` (ODC-By 1.0), the MNE-Python test files `test.edf` / `test.bdf` (BSD-3-Clause) and the OpenBCI GUI sample file `OpenBCI_GUI-v6-blinks-jawClench-alpha.txt` (MIT). - **Recording files in `fidetype live` (P4-17, gap 135).** `fidetype live --source file --path FILE` replays a recording file through the live decode. The reader comes from the adapter registry: each `file-reader` adapter declares `file_patterns` (file-name globs, case-insensitive) in `ADAPTER_INFO` (`edf`: `*.edf`, `*.bdf`; `openbci-gui`: `OpenBCI-RAW-*.txt`); `--reader ID` picks a reader by id; `--modality` sets `device.modality`; `--speed` (1 = real time, 0 = as fast as possible) now also applies to files. A file with no markers gets fixed timing. The NTS header has `fidetype.live.source = "file"`, `fidetype.file_reader` and the reader's meta keys. New in `fidetype.adapters.registry`: `file_readers`, `match_file_readers`, `pick_file_reader`, `open_file_source`; `validate` refuses a file reader without `file_patterns` or `open_source`. docs/adapters.md has a "File readers for `fidetype live`" table. The adapter template and CONTRIBUTING 7.1 say how a new reader joins. Tests: `tests/test_live_file_source.py` (an EDF+ file of the synthetic typist decodes with `builtin:synthetic-keys`; an OpenBCI GUI file by `--reader`). Text: docs/live-decode.md section 3a.

- **Offer null control (P5-31, gap 136).** `fidetype.trust.calibrate(..., offer_control="warn")` also counts the OFFERs on the null-control inputs (same decisions, no extra decoding) and compares them with the offer rate on the LTT items. Pre-stated rule: a control passes if its offer rate is at most 0.5 x the real offer rate and (it offers on at most floor(r x n) inputs or a one-sided Fisher exact test gives p <= 0.05). `ControlResult.n_offer`, `GuaranteeSheet.offers`, the printed `offer null control` lines, a sheet warning on a failure, `status.offer_null_control` on the per-policy sheet. `offer_control="refuse"` raises `NullControlError`; `"off"` keeps the pre-P5-31 sheet bytes. Default `"warn"`: no guard, `config_id` or certified status changes. `fidetype.trust.offer_control(...)` (the rule) and `fidetype.trust.recheck_offer_control(guard, inputs, null_inputs=)` (the control on a saved guard, without a new calibration). Text: docs/trust-guarantee.md section 5a.

Default `commit_unit="sentence"` unchanged (sentence-level config ids and files keep their bytes).
- **Safe WPM v0.2, PROPOSED, NOT ADOPTED (P14-26).** `safe_wpm(..., metric_version="0.2")`: prefix credit, wrong-prefix penalty, risk `wrong-prefix-commit`, optional `speech_s` (`speech_time` block); `prefix_outcome`; CLI `safe-wpm --metric-version 0.2`. - **Privacy, consent and deletion (P5-04).** New module `fidetype.trust.privacy`: `check_consent_ref` (opaque references, SEC-6), `ConsentRecord` (purposes, expiry, withdrawal; operator side), `PrivacyPolicy` and `DEFAULT_POLICY`, `delete_profile`, `erase` (deletion receipt `fidetype.deletion-receipt/1.0`); CLI `check-policy`, `check-consent-ref`, `erase`. Ledger redaction: `ProvenanceLedger.redact`, `redact_decisions`, `redact_subject`, `apply_redactions`; entry kind `redaction`; CLI `redact`. `UserProfile` checks `consent_ref` on `new` and on save.
- **Ledger hash rule `salted-body` (P5-04, default for new ledgers).** Each entry holds `salt` and `body_sha256`; the entry hash covers the body digest, so a body can be removed (tombstone) and the chain still verifies. Old ledgers keep the `v0` rule and still verify; `ProvenanceLedger(hash_rule="v0")` writes the old form.
- **LSL heartbeat and equal times (P3-10; NTS 1.0 RC4 amendment 5, LSL-C7 / LSL-C8).** `NTSOutlet` (and so `replay-to-lsl`, `fidetype live --publish lsl`) sends an empty events-stream sample after each frame and stamps markers with the time of the frame before them (option `heartbeat=True`; `replay_to_lsl(heartbeat=)`). `LSLEventSource` counts heartbeats (`stats.heartbeats`), orders equal times frame first and waits on the inlet that holds the oldest item back. The collector meets the 50 ms budget with LSL input at the receiver default window (0.05 s): implant-speech p95 `added` 1.07 ms (was 60.4 ms). The bench uses the receiver default (`--lsl-merge-window` default None; new `--no-lsl-heartbeat`). `nts-conform capture --lsl` stores one clock offset for the frames and events inlets of one host (LSL-C3), so a replayed capture keeps the equal-time order.
- **TD-14: `trust_decision` in a live input stream (P14-20; amendment 5).** `StreamingTrustLayer.push` raises `StreamEventError` (`TD_INPUT_MESSAGE`) for a `trust_decision` between the header and `end`; the collector's `validate` processor treats it as an invalid input event (cut, `consume` rejects). Same as the TypeScript and Rust `StreamValidator` (streaming cases `spec/conformance/streaming/td-input.json`). Breaking (0.x): a stream that mixed decisions into its input events was accepted live before.
- **Conformance levels and self-certification (P7-02; NTS 1.0 RC4 amendment 3).** New module `fidetype.conformance.levels` (NTS Core, NTS Full, NTS Trust-ready; `consumer_level`, `producer_level`, `level_rules`, `render_levels`) and `fidetype.conformance.certified` (`check_certified`). `nts-conform check` prints the stream level of each file and the producer level of all files; `nts-conform kit` prints the consumer level; new options `--claim`, `--binding`, `--require-level`; `{level}` in `--cmd` (and a `level` parameter in `--impl`, levels in `--verdicts`) lets an external consumer report stream levels. New sub-commands `nts-conform levels [--write|--check|--json]` and `nts-conform certified [--check]`. Reports carry `kit_version`, `producer` / `level` and per-target `stream_level`. Finer rule mapping (`fidetype.conformance.rules.REFINE`): a broad check names the rule of the finding. Kit 0.2.0 (K32 … K36, `stream_level`). Maintainer tool `tools/conformance/certify.py`.
- **MET-11 advisory check `NTS-MODALITY-MATCH` (P1-16).** A key of `emg.*`, `meg.*` or `implant.*` on a stream whose `device.modality` does not fit gives a warning. The reference consumer summary (`ConsumedStream.warnings`, `.level`) lists the advisory warnings and the stream level. Vectors V93 … V96.
- **Conformance kit and `nts-conform` (P7-01).** New console script `nts-conform` (also `python -m fidetype.conformance.nts_conform`). `nts-conform check FILE|DIR|-` finds the wire form (JSON Lines stream or decision log, NPZ, LSL or WebSocket capture, LSL stream info), runs every suite profile that applies and prints one line per finding: outcome (FAIL / WARN), the NTS 1.0 RC4 rule ids (from Appendix C.1), the check id, the location (line, frame, inlet) and the message; `--json` writes `fidetype.nts-conform.report/1`; exit 0 / 1 / 2. `nts-conform kit` runs the kit: the reference (consumer verdict + producer check), or your validator (`--cmd "PROG {path} {profile}"`, `--impl MOD:FUNC`, `--verdicts FILE`); report `fidetype.nts-conform.kit-report/1`. New modules `fidetype.conformance.kit` (the 31 kit entries, `build_kit`, `write_kit`, `kit_dir`), `fidetype.conformance.rules` (check id -> rule ids from spec Appendix C.1) and `fidetype.conformance.nts_conform`. The kit files are in `spec/conformance/kit/` and ship in the wheel. Docs: [docs/conformance.md](docs/conformance.md).
- **Drift tests (P5-09, P5-10), all opt-in; defaults unchanged.** `ConformalDriftTest(spread=True)` (also `DriftMonitor(spread=)`, `PersonalTrust(spread=)`) adds the betting functions `1 + eps * (|2p - 1| - 1/2)`, so a change of spread at the same centre raises an alarm; the anytime false-alarm bound stays the same. `PersonalTrust(guard_risk_test=True, level_guard_risk=, on_guard_risk_drift=)` runs a third conformal drift test on the guard risk (then `P(any false alarm) <= level_scores + level_risk + level_guard_risk`); `PersonalTrust.drift_summary()`. `calibration_stats` now also writes `reference_guard_risk` (the guard risk of the sampled reference items; no text), and `UserProfile.reference_guard_risk` reads it. Docs: [docs/trust-personalisation.md](docs/trust-personalisation.md) sections 4.1 and 4.2.
- **NTS 1.0 RC4, optional field types (GEN-11, gap G-12, FEP-0008).** The conformance checks refuse a wrongly typed optional field: `segment_end.reason` (FEP1-SEGMENT); `hypothesis.t_start`, `t_end`, `revision_of` and `nbest[].spans` (NTS-EVT-HYPOTHESIS); `signal_quality.channels`; `pointer.absent`, `score`, `score_semantics` (null refused); `decision.score` and `score_range` for every semantics, also an unknown one (DEC-6); header `vocab_id` and `vocab_version` (NTS-VOCAB-ID, new title); `trust_decision.reason` (all profiles); intent `vocab_id`, `pending_cleared` (INT-T8); control `level` without `radius` (CTL-T8). The latency fields (TIM-4) are checked on every event of registry 12.1, frames included (`fidetype.conformance.io.TIMING_KEYS`, `TIMED_TYPES`, `RawStream.timed`). Vectors V69-V82, F63-F66, D24-D26, I25, C25, E25-E27 (330 in all); same behaviour as the TypeScript and Rust SDKs.
- **NTS 1.0 RC4, MET-3 (SC-2):** `fidetype.conformance.checks.PLANNED_NAMESPACES` (`emg`, `eeg`, `meg`, `fnirs`, `implant`). A custom `meta` key in a planned namespace gets the NTS-NAMESPACE warning (advisory).
- `tools/semconv/semconv.py`: the spec type "non-empty string", the attribute field `registered_values` (open lists, SC-4), `resolved_questions` in the manifest, and a check that the three SDKs list the same planned namespaces as the registry.
- **NTS 1.0 RC3, unknown enumeration values (VER-6 … VER-10, FEP-0007).** New helpers `fidetype.streams.spec.is_newer_minor`, `enum_ok`, `is_unknown`. In data whose governing version is a newer minor version (`"1.1"` …), every conformance check accepts an unknown enumeration string (header, event, decision, intent and control declaration values); `"0.1"` and `"1.0"` data still refuse it. Comparison rules skip unknown values. The consumers never act on them (VER-10): no actuation of an intent COMMIT with an unknown `risk_class`, `role` or `confirmed_via`; no motion on an unknown control state; after an unknown state the control counts as not engaged (CTL-S7). Vectors V66-V68, F57-F59, I24, D22, D23, C24, E22-E24; same behaviour as the TypeScript and Rust SDKs.
- The validators of `fidetype.trust.intent` (`validate_intent_declaration`, `validate_intent_event`, `validate_feedback_event`) and `fidetype.trust.control` (`validate_control_declaration`, `validate_control_event`, `validate_enable_event`, `ControlDeclaration.from_declaration`) take an optional `lenient` argument (default `False`, the RC2 behaviour). The reference trust layers stay strict.
- `StreamWriter(vocab=[])` writes a hypothesis-only (or control-only) stream, as spec HDR-12 allows. `blank_id` must then be `None` (HDR-6). With an empty vocab the writer refuses every frame: `frame()` (all three input forms), `frames()` and `event({"type": "frame", ...})` raise `ValueError` (HDR-12).
- `StreamWriter(extra_header={...})` adds header keys (for example `clock_domain`, `decode_declaration`) before `meta`, like `extraHeader` (TypeScript) and `extra_header` (Rust). It must not hold a key that the writer sets itself.

- Conformance vectors V62-V65 (`spec/conformance/v0.1`, 65 vectors now): empty vocab with hypotheses only (accept); empty vocab with a dense frame, with a sparse frame, or with `blank_id` 0 (reject).

### Fixed

- **OpenBCI GUI millisecond time stamps (P4-16).** The GUI sample files write `Timestamp` in Unix milliseconds. The reader took them as seconds: `t0` was about 1.6e12 s and the float64 sample times lost their spacing (conformance `SRC-TIME`: 1/256 s instead of 1/250 s). A first stamp above 1e11 is now read as milliseconds. A GUI v4 file (no column-name line) now gives a clear `ValueError` message. Tests: `test_openbci_gui_millisecond_stamps`, `test_openbci_gui_v4_file_has_a_clear_message`.
- **`fidetype live --source file` with non-key markers (P4-16).** A file whose markers include no `keypress` (for example the PhysioNet EDF+ annotations `T0` / `T1` / `T2`) kept marker timing and made 0 windows. It now gets fixed timing with a note, as a file with no markers. Test: `test_cli_file_without_keypress_markers_uses_fixed_timing`.

### Changed
- **Bounded memory of the vector beam search (P5-32, gap 137).** `IncrementalPrefixBeam(search="vector")` (and `ctc_prefix_beam_search(search="vector")`, the built-in drop-in decoder) cuts its per-prefix caches (`lm_score`, the LM rows `lm_arr` and the owner's LM rows) to the current beam when they pass `PREFIX_CACHE_MAX`, as the loop search does since P14-41. Results are exactly the same. On a long near-uniform null input (T = 10,000, V = 98) the search peak falls from 59 MB (growth T^2) to 22 MB (linear in T); `tests/test_trust_incremental.py::test_long_null_input_memory_is_bounded` checks a stated limit.
- **`safe_wpm`: no `certified` for an infeasible guarantee when the policy commits (P5-30, gap 96).** A guarantee with `feasible: false` now certifies only a policy that commits nothing (`vacuous`). If the policy commits on one trial or more, the status is `not-certified`, the value is None and the note names P5-30 (v0.1 and the proposed v0.2). Rule 6 in docs/safe-wpm.md. No committed score card changes label.
- **`GroundingCheck.apply` returns the list sorted by the new score (P15-27, gap 94).** Before, a demoted (ungrounded) candidate kept its place, so `out[0]` could be a candidate that fails the gate while `NBest` and the trust layer used the best grounded one. Now `out[0]` is the same top-1 (stable sort; deficits stay in input order). Trust decisions do not change; only code that reads `out[0]` directly does (P15-05 B1 T15 M4-13 WER 0.1617 -> 0.1609).
- **Breaking (0.x): default-deny update gate (P15-13, gap 1).** `GuardedUpdateLoop(challenger_test="noninferiority")` is the new default: a challenger must show that it is not materially worse than the champion (top-1 right / wrong, CER of the top-1 texts as tie-break when the truth is known; a pair with unknown truth counts as worse unless the texts are equal, the challenger is right or the champion is known wrong). Exact one-sided tests at `challenger_level` (0.05, Bonferroni): worse share among differing pairs < 0.5 + `challenger_margin` (0.1) or worse share of all items < `challenger_margin_abs` (0.1). Few labelled items give a rejection, never an acceptance. Reason: the P15-02 sign test counted unknown truth as wrong for both sides and accepted a time-reversed decoder under partial feedback (P15-03a, H3). `challenger_test="sign"` keeps the old test, its record keys and its loop `config_id`s; the new gate adds a `challenger` field to the loop `config_id` payload. `add_check_item(truth=, not_truth=)`; `TrustGuardUpdater.propose` / `propose_calibration` accept `check_texts[i] = None` (unknown) and `check_rejected=`. `ChallengerTest` has new fields (`method`, `n_unknown`, `p_noninferior`, `p_abs`, `passed_by`, `legacy_*`).
- **Breaking (0.x): no champion outputs, no acceptance (P15-23, gap 71).** With the default `challenger_test="noninferiority"`, `GuardedUpdateLoop.finish_update` refuses a challenger whose champion outputs are missing for some or all check items (reason "no champion outputs for k of N check items"). Before, the comparison was skipped and the challenger could pass on the null controls and the block LTT alone. Opt-out: `GuardedUpdateLoop(allow_missing_champion=True)` (recorded in `UpdateRecord.notes` and in the config id). `challenger_test="sign"` keeps the P15-02 behaviour. `TrustGuardUpdater` and `PersonalTrust` always give the champion outputs and are not affected.
- **Same-decoder re-calibration rule (P15-24, gap 72).** `GuardedUpdateLoop.new_version(..., kind="recalibration")` (ledger proposal `details.kind`) and `recalibration_rule="absolute"` (default; `"decoder"` = the P15-13 rule): a re-calibration of the same decoder passes on identical top-1 texts or on the absolute branch alone at the full level (`P(Bin(N, margin_abs) <= w) <= level`; `N = 48`: up to 1 worse item instead of 0). The documented gate guarantee still holds for every proposal. `ChallengerTest.rule`. `TrustGuardUpdater.propose(..., kind=None)` sets `"recalibration"` only without `champion_inputs` and with `fidetype.trust.update_hooks.same_decoder(candidate, live)`. `PersonalTrust` re-calibrations keep the live decoder's `decoder_name` / `decoder_version` / `modality` unless `calibrate_kwargs` set them (so its candidate config ids change).
- **Trust `config_id` no longer depends on how the decoder script is loaded (P5-21, gap 59).** `calibrate()` writes the recipe field `decoder` of a custom `decode_fn` without the Python module path (`custom:<qualname>`; before: `custom:__main__.<qualname>` when run, `custom:<import name>.<qualname>` when imported) and adds `decoder_id = "<decoder_name>@<decoder_version>"`. New ids for every guard calibrated with your own `decode_fn` (version bump of the id, not of the file format); saved guard files keep their bytes and their ids; `calibrate(decoder_label="module")` reproduces an old id. The guarantee sheet still shows the label with the module path.
- **Collector refuses an input-event file that would mix streams (P5-17).** A `jsonl` exporter of input events without `{session}` in its path is a configuration error when its pipelines can carry more than one stream (several receivers, several file paths, a websocket or LSL receiver). The P3-04 bench writes `out/streams/{session}.nts.jsonl` (`bench.stream_files`).
- `spanishbcbl_meg.stream_meta` writes `data.licence` instead of the custom key `spanishbcbl.licence`.
- **Breaking (0.x): `fidetype live --out` writes no `trust_decision` events any more (P14-17, gap 42).** The `--out` file is now a pure NTS input stream (header, frames, final hypotheses, `segment_end`, `lsl_status`, `end`). The trust decisions go to a separate FEP-0001 decision log: new option `--decisions-out FILE`; default with `--out S.jsonl`: `S.decisions.jsonl`; `--decisions-out none` turns it off. Before, the file mixed both, and `nts-conform check` failed it (TD-4, FEP1-TD-INPUT). A script that read the decisions from the `--out` file must read the decision log now. `fidetype.live.runner.make_writer(path, ..., decisions=PATH)` splits the same way; `fidetype.live.publish.EventTee(..., decisions_file=)` does the split; the run summary has `decisions_out`. The P14-11 CI replay (`tools/ci/kt_lsl_replay.py`) checks both files with `nts-conform check --require-level trust-ready`.
- **New core check `NTS-TD-INPUT` in the v0.1 suite (TD-4; NTS 1.0 RC4 amendment 4).** `fidetype validate` (and `fidetype conformance check`, the reference consumer `consume`) read a `trust_decision` line in an input stream as an unknown event type and ignored it, so they passed a file that `nts-conform check` failed. Now they reject it. `RawStream.td_lines` lists the lines. Vector V97 (97 v0.1 vectors). Same check in the TypeScript and Rust SDKs.
- **GEN-10 (RC3):** a JSON integer above 2^53 - 1 in magnitude is not an integer. The conformance readers parse with the `json_int` hook (`fidetype.streams.spec.json_int`, `MAX_JSON_INT`), which turns such a literal into a float, so every integer check refuses it. Vectors F60, F61, W44.
- **TD-F2 (RC3):** a `trust_decision` whose `declaration` is not an object is refused (vector F62).
- **PRF-4 (RC3):** the text "acted" lists of the `fep-0001` and `fep-0003` consumers (and `offered`, TD-12) use only decisions with `profile` absent or `"text"` (`fep0001.is_text_decision`). A final COMMIT of an unknown profile is never acted on.
- The package version has one source: `__version__` in `src/fidetype/__init__.py`.
- `fidetype.adapters.text_nbest` writes through `StreamWriter` (`vocab = []`) instead of its own JSON Lines. The output is equivalent: the same events and values; only a `segment_end` with a time now has the key order `type`, `t`, `unit` (the writer order in all three SDKs). All checks still run before the file is written.
- `NTS-NORM` reports a frame of a stream with an empty vocab as not normalised (log-sum-exp -inf), as TypeScript and Rust do. Before, the check raised an internal error (same verdict).

### Deprecated
- **`PretrainedDecoder.decode(path)` (P14-44).** `decode()` is for one input array (one stream). A path still returns the list of `decode_file(path)`, with a `DeprecationWarning`; use `decode_file()` for files.
