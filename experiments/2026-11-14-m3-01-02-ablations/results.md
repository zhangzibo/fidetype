# M3-01 / M3-02: trust-core ablations (frozen v4 baseline), MEG and simulator end to end

Tasks M3-02 (ablations) and M3-01 (SpanishBCBL MEG and simulator). CPU only, no retraining, cached Paper 1 decodes where they exist. The plan ([plan.md](plan.md), commit `f5bd2d5`) was committed before the first run. Full tables: [results/tables.md](results/tables.md) (generated by [tables.py](tables.py)). Numbers: `results/*.json` (aggregated only). Logs: `results/run-*.log`.

Run (repo root, each under `python -m fidetype.utils.isolation run --class background --threads 1 --`):
`.venv/Scripts/python.exe -I experiments/2026-11-14-m3-01-02-ablations/run_b2t.py --which ours` (and `--which published`, `--stage splits`), `run_emg.py`, `run_meg.py [--runs ... --out ...]`, `run_sim.py --conds ... --out ...`, then `tables.py`. Wall time: B2T 5 min per decoder, sEMG 3 min, MEG 11-25 min per run, simulator ~15 min per condition.

## Reproduction check
The v4 baseline reproduces Paper 1 exactly on all four fixed B2T splits (same λ, same counts as the committed clean-drift items): ours A 20/816 = 0.0245 (commit 0.100, eWPM 11.48), ours B 42/816 = 0.0515, published A 24/816 = 0.0294 (0.403, 18.65), published B 25/816 = 0.0306. Controls: ours 0/300 frame-shuffled and uniform, as `v4-derived`. Repeated splits: v4 > α in 15/200 (ours) and 11/200 (published), as R4. MEG r4b-full-medium: 0 commits, eWPM 3.20, as Paper 1.

### Findings (M3-02)
1. **LTT is the module that holds the guarantee.** Without risk control (plug-in grid threshold), 27-31 % of B2T re-splits exceed α; CRC 18-19 %; LTT max 6-8 % (≤ δ = 0.1). On fixed splits the plug-in threshold is often already at the LTT value (ours A, all sEMG), so the fixed-split effect is zero there and +0.017 to +0.018 on the published gate.
2. **The max combine matters on sEMG.** LTT alone (λ below the grid value) raises sEMG wrong commits 0.0036 → 0.022 / 0.031 and commits on 3/200 frame-shuffled streams. On B2T it raises the re-split exceedance 0.075 → 0.145.
3. **The guard is a control-safety module, not an accuracy module.** On real B2T data, guard off is as safe or safer (re-splits: ours 0/200 > α, published 1/200; split B −0.022). But with the guard off our decoder commits 198/300 uniform and 3/300 frame-shuffled streams. It has no effect on sEMG and MEG (the grid sets `commit_max_risk` 1.0 there).
4. **Calibration is the module that stops commits on weak decoders.** Without it, MEG commits 21 of 637 test items and 20 are wrong (0.031 [0.019, 0.048], below α, so LTT allows it), plus 6/637 shuffled-MEG commits. On B2T ours split A wrong commits double (0.0245 → 0.0527, Holm p 6e-4). On split B the uncalibrated grid never commits. sEMG xsubject: calibration off raises eWPM 4.08 → 4.76 with 0 commits (the frame temperature changes the decode; R1 found the same).
5. **No single module is enough alone.** "Guard alone" gives the worst real-data rates (B2T ours 0.071 / 0.097, sEMG calib 0.045) and commits on sEMG controls (uniform 33/200). "Calibration alone" fails the B2T uniform control. Only the composition (calibration + guard + LTT max) has 0 control commits on every dataset and ≤ δ re-split exceedance.
6. **Conformal sets affect speed only** (eWPM −0.03 to −0.10 when off; no wrong-commit change).
7. **Commit gate B and the session monitor are nearly free and nearly inert on Paper 1 data.** Gate B blocks 0 B2T commits and 1 / 7 / 0 sEMG commits (xsession wrong 2 → 1). The monitor raised 1 alarm in 14 published sessions (one wrong commit fewer) and none elsewhere; on re-splits it never raised a split's rate. Their value is on the cases they target (empty commits on T12, M2-18; bad days, A2), not on these sets.
8. **The declaration check is needed, but "abstain" is expensive.** A producer that decodes the raw stream (temperature 1.0) against a configuration frozen at T 3.8 raises wrong commits to 0.080 / 0.099 (ours) and 0.052 / 0.055 (published): above α on all 4 splits. Check "warn" (default) flags all 816 mismatches but keeps the decisions. Check "abstain" gives 0 commits but also no offers, so eWPM falls to 3.55 (below gaze 4.08; offer-only gives 11.42 / 18.11). Suggestion (not applied): a check mode "offer-only".

Control commits = shuffled MEG + zero MEG (the decoder's real outputs) + frame-shuffled + uniform, 637 each.

- **v4 makes 0 commits in all 5 runs, and this is the correct result.** The decoder is too weak: at most 5 of 637 top-1 sentences are right, and the truth is in the n-best for at most 12 of 637. Every eligible calibration item is wrong (0-7 per run), so LTT cannot certify any threshold. The one-sided 95 % bound on the wrong-commit rate is 0.0047 per run.
- **What it shows:** the layer stays safe on a decoder that is near chance at sentence level. It does not make MEG useful: eWPM 2.95-3.20 against gaze typing at 3.15 (only the Paper 1 run and seed 1 / r5 are above gaze, by 0.01-0.05). Usefulness needs a stronger MEG decoder, not a different trust setting.
- **Calibration is what stops MEG commits.** Without it, the Paper 1 run commits 21 items, 20 of them wrong. That is 20/637 = 0.031 < α, so LTT accepts the threshold. It also commits on 7 control streams (6 shuffled MEG, 1 frame-shuffled). r4b-full: 8 of 8 wrong, 4 control commits.
- The streaming layer equals the batch decisions in 3,185 of 3,185 cases. Commit gate B and the monitor change nothing (0 commits to block, 0 alarms).

- **End to end works.** Each condition: fit the v4 recipe, freeze it (`FrozenTrustConfig`), replay the 300 test streams through `StreamingTrustLayer` (frames route). The streaming commit decisions equal the batch decisions in 1,800 of 1,800 cases. v4 wrong-commit 0.013-0.047 (all ≤ α), always commit 0.10-0.32.
- **The frame temperature fit recovers the distortion** (fitted 2.00-2.01 for T 0.5, 0.50-0.51 for T 2.0, as M2). Calibration off costs 2.4-7.5 eWPM on distorted streams: the frame temperature changes the beam search, not only the confidence.
- **Risk control** lowers wrong commits by 0 to 0.070 (median T 0.5: 0.117 → 0.047, Holm p 1e-5).
- **The guard blocks empty commits on zero input.** The zero-input stand-in decodes to an empty text. With the guard off, 73-81 of 100 such streams are committed (empty commits, the M2-18 failure). v4 commits none.
- **Surprise: v4 commits on frame-shuffled simulator streams** (1-16 of 100, all wrong). The simulator's frames are sharp, independent key peaks, so a shuffled stream keeps high frame confidence, and the in-domain LM turns the shuffled characters into a fluent template sentence (for example a shuffled stream decodes to "the cook liked a fresh pizza ..."). The guard sees confident frames and a consistent n-best. On real B2T, sEMG and MEG streams, v4 commits 0 frame-shuffled streams. Gate B does not help (the texts are not empty). This is a limit of the guard's evidence term (it trusts confident frames) and of the simulator (no temporal structure inside a key).
- **Declaration check:** a raw-decoding producer changes wrong commits by −0.030 to +0.003 here; for T 2.0 (under-confident) the raw decode gives no commit at all. Check "abstain" gives 0 commits. With the default `UserConfig`, ABSTAIN loses the sentence, so eWPM is 0 for those rows (user-model property; B2T uses `aac_gaze` with fallback typing).
- Commit gate B blocked 0 commits; the monitor raised no alarm (one session per condition).

## Deviations from the plan
- Simulator: one attempt per item (`max_attempts = 1`, as the streaming layer and the real-data runs). With two attempts and regenerated streams, the item tables of the M2-13 method do not hold (a first run stopped on that check). Monitor session = all 300 test items of a condition (plan.md did not fix a session for the simulator).
- MEG provenance streams store the participant as `spanishbcbl.participant`; the loader maps it to `participant` (decodes and cache keys unchanged).
- "Declaration abstain" rows come from the streaming layer (hypothesis route, B2T split A and the simulator); there is no batch equivalent.

## Limitations
- Another agent's uncommitted, value-neutral change (an edit-distance cache bound in `trust/guard.py` and `trust/_align.py`) was in the working tree during the runs. The exact Paper 1 reproduction shows no effect.
- Fixed-split McNemar tests are conditional on one fitted pipeline per split. Re-split numbers share trials (descriptive).
- B2T zero input is a stand-in (every frame = the first frame); the T15 RNN is not available.
- The simulator LM is in-domain (template sentences), so simulator decoders are optimistic.
- Gate B and the monitor were tested where Paper 1 data allow; their target failures (empty commits, a bad day) are rare here.
