Fidetype trust layer: live demo

A simulated neural decoder sends NeuralTextStream frames. The streaming trust layer reads them and decides for each phrase: COMMIT (type the text), OFFER (show the text; the user confirms or rejects it) or ABSTAIN (type nothing). Grey previews are provisional decisions while the signal arrives; a consumer never types them. All data on this page is synthetic. Nothing is sent over a network.

No signal, no text. On 40 flat (no-signal) streams, the decoder's language model still writes text made of real words. "Always commit" types it every time (40/40). The trust layer typed 0/40: the hallucination guard sees that the characters have no neural evidence and abstains. Paper 1 reports the same result on real data: no text committed from null input.

Set-up

  • Decoder: ReferenceDecoder (beam 8) + character 5-gram LM, fitted on other synthetic phrases. Frames at 25 Hz; a provisional decision every 25 frames.
  • Signal levels: simulator target CER 0.05 (strong), 0.17 (good), 0.28 (medium), 0.41 (weak); confidence temperature 0.5 (over-confident, as real decoders). Null inputs: a flat (near-uniform) stream and a frame-shuffled stream.
  • Trust configuration tcfg-a34f63a757f55371 (frozen, Paper 1 recipe, fitted on synthetic data): COMMIT if p ≥ 0.78 and guard risk ≤ 0.2; ABSTAIN if guard risk ≥ 0.8; else OFFER the top 1. Commit threshold from ltt-binomial (alpha 0.05, delta 0.1, n = 150). One attempt per phrase, so the layer never asks for a repeat.
  • Synthetic results show how the layer behaves. They are not a measurement of a real device. Real results: Paper 1 and the open benchmark.
  • Reproduce: install Fidetype from the repository (pip install .), then fidetype demo --html demo.html. Fidetype 0.0.1; generated by fidetype demo, do not edit by hand.
