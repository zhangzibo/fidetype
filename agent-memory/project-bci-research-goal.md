The user started stealth-project on 2026-11-07 as a long-term, public brain-computer-interface project. It was inspired by Meta FAIR's Brain2Qwerty (MEG typing decoding, v1 Nature Neuroscience 2026 and v2 preprint). Possible outcomes are research papers or a real-world application. The user first wanted to begin with research, with the direction open. On 2026-11-07 the direction was chosen: **trustworthy neural text entry**, a decoder-agnostic trust layer (calibration, abstention, hallucination checks, provenance) on top of brain-to-text decoders. On 2026-11-08 the user named the project **Fidetype**: package `fidetype`, GitHub repo zhangzibo/fidetype (renamed from stealth-project). The plan targets M0 by 2026-11-09 and M1-M7 by 2026-11-15 (the user's target), tracked in `wiki/progress/tracker.json`.

**Scope decision (2026-11-08):** The user wants Fidetype to be a big, OpenTelemetry-level project: **the vendor-neutral standard and trust layer for neural input**, i.e. text or intent decoded from any modality (consumer wrist EMG such as Meta Neural Band, EEG headsets, MEG/OPM-MEG, implants such as Synchron/Neuralink via interfaces like Apple BCI HID). NeuralTextStream becomes a modality- and vocabulary-agnostic spec (`spec/neuraltextstream-v0.1.md`) with OTel-style semantic conventions. Adapters for all modalities are first-class. Governance is founder-led now, with a written path to a foundation (LF AI & Data or NumFOCUS). Research MEG (SpanishBCBL) stays the credibility base and the Paper 1 test case. The success metric is the number of decoders and devices that emit NeuralTextStream, not stars. The user accepts a multi-year horizon and the need for outside partners, people and funding; the 1-week targets apply to building the code, not to adoption. Licence-clean data (CC0/CC BY or own) matters more now; emg2qwerty is CC BY-NC, research only. Recorded in `wiki/questions/direction-decision.md`.

**Build-it-all decision (2026-11-10):** M1-M7 are only v0.1. The user wants full OTel-scale standardisation and wants us to build all of it ourselves: spec to 1.0 with an RFC process, multi-language SDKs, a collector-style pipeline, device/toolkit/dataset-replay adapters, a public eWPM benchmark, conformance/certification, docs/site, governance. Subagents write the code and docs. The user owns outward-facing work (outreach, partners, arXiv endorsement, ethics). Adoption order: demo + benchmark → paper → targeted communities → direct contact with 5–10 groups. Long-term plan: `wiki/questions/roadmap-standard.md`.

**Scope made explicit (2026-11-11):** the roadmap explicitly includes (A) intent beyond text: cursor, clicks, commands, speech, with trust gating for actuation; and (C) a public benchmark hub/leaderboard. The user said "no need to change prio": text entry stays first, and A and C are added to later phases, not moved earlier. The user sees this as expansion, not a change of direction.

**Why:** BCI has been a long-held interest. The user thinks it is the next big field after AI and is under-invested.
**How to apply:** Research is kept as a Karpathy-style LLM wiki: the raw sources are in `references/` and the pages I maintain are in `wiki/`. The schema is in `CLAUDE.md`. `references/papers/` and `references/repos/` are git-ignored because of licences. Meta's code is CC BY-NC 4.0, so anything that might go commercial needs its own implementation. Also note the user has no MEG/EEG hardware, so prefer directions that work with public data. The machine has an AMD RX 7800 XT (16 GB, no CUDA, so it needs ROCm), a Ryzen 7 9800X3D, 31 GB RAM and about 1.1 TB free on C:. The user considers this a weak GPU.
